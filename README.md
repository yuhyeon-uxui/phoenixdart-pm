# MVP Scope and Workflow Scenarios

## Service Definition

피닉스다트 운영형 워크플로우 프로젝트 관리 툴

기본은 프로젝트 관리 툴이지만, MVP의 핵심은 팀 간 전달, 확인, 일정 응답, QA 대응, 오픈 상태 관리에 있습니다.

## Core Scenarios

### 1. 프로젝트 등록

1. 프로젝트 오너가 새 프로젝트를 등록한다.
2. 프로젝트 유형, 운영 속성, 담당자, 기간, 상태를 입력한다.
3. 초기 업무와 참여 팀을 설정한다.

### 2. 단계 전달

1. 디자인팀이 작업을 완료한다.
2. 개발팀으로 전달 처리한다.
3. 개발팀이 전달을 확인한다.
4. 개발 예상 일정을 입력한다.
5. 프로젝트 오너 또는 이전 팀이 그 일정을 확인한다.

### 3. QA 흐름

1. 개발 완료 후 디자인 QA 또는 기능 QA를 요청한다.
2. QA 담당자가 확인하고 일정을 입력한다.
3. QA 이슈를 등록한다.
4. 수정 후 재검증 상태를 갱신한다.
5. QA 완료 처리한다.

### 4. 로컬라이징 및 최종 검수

1. 로컬라이징 팀에 전달한다.
2. 언어별 검수 담당자가 확인한다.
3. 일정 또는 완료 여부를 회신한다.
4. 최종 담당자가 전체 완료 상태를 확인한다.

### 5. 배포와 오픈

1. 배포 준비 상태로 전환한다.
2. 배포 완료 처리한다.
3. 실제 오픈 여부를 별도로 기록한다.
4. 운영중인지, 내부 오픈인지, 전체 오픈인지 구분한다.

## Main Dashboard Priorities

- 지금 진행 중인 프로젝트
- 다음 팀 확인 대기 중인 프로젝트
- 일정 회신이 아직 안 온 프로젝트
- QA/오픈 이슈가 남아 있는 프로젝트
- 오늘 기준 대응이 필요한 업무

## Progress Rule

MVP에서는 진행률을 아래 기준으로 계산합니다.

`완료 업무 수 / 전체 업무 수 * 100`

이후 확장 시에는 아래 보조 지표를 추가할 수 있습니다.

- 단계 완료율
- 팀 확인율
- QA 완료율
- 오픈 준비율

## MVP Included

- 프로젝트 등록
- 업무 등록/수정
- 상태 관리
- QA 이슈 등록
- 진행률 자동 계산
- 단계별 전달/확인/일정 회신 구조
- 오픈 상태 관리
- 리스트 보기 / 칸반 보기

## MVP Excluded

- 권한 체계 고도화
- 자동 알림
- 외부 툴 연동
- 드래그앤드롭 고도화
- 고급 간트/리소스 관리
- 복잡한 승인 워크플로우 엔진

## IA / Pages

- `/` 메인 대시보드
- `/projects` 프로젝트 목록 성격의 진입
- `/projects/new` 프로젝트 생성
- `/project/:id` 프로젝트 상세
- `/inbox` 확인/전달 대기함
