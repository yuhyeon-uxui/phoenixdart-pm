# User Scenarios

## Service Definition

피닉스다트 운영형 워크플로우 프로젝트 관리 툴

기본은 프로젝트 관리 툴이지만, MVP의 핵심은 팀 간 전달, 확인, 일정 응답, QA 대응, 오픈 상태 관리에 있습니다.

## Core Scenarios

### 1. 프로젝트 등록

1. 프로젝트 오너가 새 프로젝트를 등록한다.
2. 프로젝트 유형, 운영 속성, 담당자, 기간, 상태를 입력한다.
3. 초기 업무와 참여 팀을 설정한다.

### 2. 단계 전달

1. 디자인팀이 작업을 완료한다.
2. 개발팀으로 전달 처리한다.
3. 개발팀이 전달을 확인한다.
4. 개발 예상 일정을 입력한다.
5. 프로젝트 오너 또는 이전 팀이 그 일정을 확인한다.

### 3. QA 흐름

1. 개발 완료 후 디자인 QA 또는 기능 QA를 요청한다.
2. QA 담당자가 확인하고 일정을 입력한다.
3. QA 이슈를 등록한다.
4. 수정 후 재검증 상태를 갱신한다.
5. QA 완료 처리한다.

### 4. 로컬라이징 및 최종 검수

1. 로컬라이징 팀에 전달한다.
2. 언어별 검수 담당자가 확인한다.
3. 일정 또는 완료 여부를 회신한다.
4. 최종 담당자가 전체 완료 상태를 확인한다.

### 5. 배포와 오픈

1. 배포 준비 상태로 전환한다.
2. 배포 완료 처리한다.
3. 실제 오픈 여부를 별도로 기록한다.
4. 운영중인지, 내부 오픈인지, 전체 오픈인지 구분한다.
